    1. Profile

    List account activity

    Keyset-paginated activity feed (trades, splits, merges, redeems, …) in the standard { data, pagination } envelope.

    Ordering is (block_timestamp, sequence_id), DESC by default or ASC via sort_direction=ASC; both keyset-seekable. Value sorts (CASH/TOKENS) have no seek anchor and are rejected with 400 rather than silently re-served as page one. The cursor binds the direction it was minted under and the resume ADOPTS it, so a replay cannot flip the walk mid-stream.

    A malformed condition id is a 400 naming the value; a well-formed one that matches nothing serves an empty data array, which is the meaningful zero-state; absence means the market is not servable, and only that.

    Query Parameters

    ​
    user
    string | null

    Required; the feed is user-anchored.

    ​
    limit
    integer<int32> | null

    Page size; default 100, max 1000, past-cap rejected.

    Required range: 0 <= x <= 1000
    ​
    cursor
    string | null

    Opaque cursor from a prior response's next_cursor; binds the sort direction it was minted under.

    ​
    type
    string | null

    Activity type(s), comma-separated. Accepted values: TRADE, SPLIT, MERGE, REDEEM (automatic redemptions included), CONVERSION, MIGRATION, REWARD, YIELD, MAKER_REBATE, TAKER_REBATE, REFERRAL_REWARD, DEPOSIT, WITHDRAWAL, DIRECTIONAL_SPLIT, DIRECTIONAL_MERGE, THRESHOLD_COMPOSE, THRESHOLD_DECOMPOSE, TIP. Any other value is rejected with 400. Omitted, the feed returns every type except TIP.

    DEPOSIT and WITHDRAWAL rows are returned only with exclude_deposits_withdrawals=false. Under its default (true) they are dropped even when named here, so type=DEPOSIT or type=WITHDRAWAL alone returns an empty page.

    DIRECTIONAL_SPLIT, DIRECTIONAL_MERGE, THRESHOLD_COMPOSE and THRESHOLD_DECOMPOSE are operations on range events, whose outcomes are value buckets and whose lines are ABOVE / BELOW positions over those buckets. A directional split turns collateral plus the buckets between two lines into ABOVE the lower line and BELOW the higher one; a directional merge reverses it. Both are rows of the whole event, so a condition filter never returns them. A threshold compose turns buckets into one line position and a threshold decompose turns it back; these rows carry the line's market and side. Split, merge, redeem and conversion on a range event keep SPLIT, MERGE, REDEEM and CONVERSION.

    TIP is opt-in: it is never in the default set, so it is only returned when you name it here. A tip is a user↔user pUSD transfer that is not a trade-settlement leg; size is the amount and side carries the direction (IN received / OUT sent).

    ​
    condition
    string | null

    Condition id(s), comma-separated (at most 20 distinct values). condition_id / conditionId are accepted aliases.

    ​
    event_id
    string | null

    Gamma event id(s), comma-separated (at most 20 distinct values); resolves to the events' markets. Mutually exclusive with condition.

    ​
    side
    string | null

    BUY or SELL.

    ​
    start
    integer<int64> | null

    Window start on block_timestamp, epoch seconds (inclusive). Omitted or 0 floors to three years back; pass start=1 for full history.

    ​
    end
    integer<int64> | null

    Window end, epoch seconds (inclusive); omitted or 0 means now plus one day.

    ​
    sort_by
    string | null

    Only TIMESTAMP is supported (v2 pages by keyset).

    ​
    sort_direction
    string | null

    ASC or DESC (default). The keyset seeks in the chosen direction; the minted cursor binds it, so pass it consistently when paging.

    ​
    exclude_deposits_withdrawals
    boolean | null

    Defaults to true, which drops DEPOSIT and WITHDRAWAL rows from the page, including when type names them. Pass false to include them.
